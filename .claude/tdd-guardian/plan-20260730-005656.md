  - Registry→CLI coverage: for each op's CLI projection, assert a subparser/verb exists; assert no extra CLI verb lacks a registry entry — assertion level: Level 1.
  - Capability parity: assert every `experimental`/gated op is labeled/gated on both surfaces (drive both `handle` and `main` for `review`) — assertion level: Level 3.
  - Layering extension: the extended AST scan asserts no core/registry/service module imports `cli`/`mcp_server`, adapters don't import each other, and both route through `console` — assertion level: Level 3 (real AST import analysis over the package).
  - Drift tripwire: a synthetic "extra tool with no registry entry" / "op renamed off its alias" fixture makes the parity test fail (negative test proving the guard bites) — assertion level: Level 1.

## Risks & Assumptions
- **100% branch coverage, no-decrease** (`.claude/tdd-guardian/config.json`): every new taxonomy arm (six in WI-5), every capability arm (WI-6), and every adapter error/fan-out branch (WI-7) needs an explicit reaching test. Hard-to-reach branches must be covered by targeted fixtures, not `# pragma: no cover`; if any ignore is unavoidable, use range-form ignores per policy-core, never line-count form.
- **`query.py`/`console.py` must stay unchanged.** Assumption: the six-value grounding taxonomy is composable at the service layer from `query.verify` (found/not-found/folded/None) + `query.source_of` (install-state) + `check.py` sha256 (stale), with `ambiguous` produced at the `locate` step. RISK: if `ambiguous` or `source-stale` genuinely cannot be derived without touching `query.verify`/`query.Source`, that is a flagged deviation requiring explicit sign-off — do not modify them silently (WI-5 acceptance encodes this).
- **`source_sha256` reuse (WI-5).** Assumption: the hashing in `check.py._check_freshness` can be extracted into a small pure helper without changing `check`'s existing behavior/output. RISK: `_check_freshness` is currently private and coupled to `Report`; extraction touches `check.py` (not `query`/`console`), which is acceptable but must preserve `lode check` behavior (covered by existing tests staying green).
- **Judge identity (WI-6).** `FixtureJudge`/`Verdict`/`Score` have no identity or `non_production` field today. Assumption: the supervision service can wrap and label without modifying `gate/` internals (derive identity from the judge instance). RISK: if a `judge_identity` field must be added to the `Judge` protocol or `Verdict`, flag it; prefer the wrapping approach.
- **Schema-test churn (WI-7).** `tests/test_mcp_schema.py` asserts the exact `_EXPECTED_TOOLS` set and `DISPATCH == tools − {list_kbs}`. Refactoring the adapter to project the registry will change the internal `DISPATCH` structure. Distinguish the HARD contract (the 8 tool names + schemas must not change) from the internal mechanism (the test may be rewritten to point at the registry projection). Rewriting these tests to assert the same external guarantees via the new mechanism is sanctioned; changing any tool NAME is not.
- **Byte-identical output contract.** The MCP `[kb]` tag currently prefixes grounding and tagged discovery, while single-KB untagged discovery is byte-identical to a direct call. Moving provenance into the core risks perturbing discovery formatting; WI-7 must preserve it (characterization test).
- **"Citation found ≠ claim verified" is a correctness-critical framing**, not cosmetics. The grounding result and both renderings must make textual-occurrence-only unmistakable; a regression here is a truth-safety defect, not a wording nit.
- **Zero new runtime dependencies** (`pyproject.toml dependencies = []`): the spec, registry, services, and parity tests are all stdlib. `entail`/NLI stays an opt-in dev extra and off the default path.
- **DRY / altitude.** The services must not re-implement retrieval, consult projection, zoom, or verification. A reviewer/behavioral check guards against duplication (WI-4 acceptance).
- **Sequencing is shippability-driven.** Each WI keeps the suite green independently; WI-1 (spec) and WI-3 (registry) land before either adapter is touched so drift is caught structurally from the first adapter change.

## Deferred / Out of Scope
- The real calibrated LLM judge (two-step, position-debiased, gold-set-calibrated). Only the stable `review` operation + capability gating + non-production labeling is plumbed; the judge stays `FixtureJudge`.
- `entail`/NLI as anything other than an opt-in, advisory, warn-only capability — it is never wired into the default `verify` path.
- Any change to the card format / `dev-docs/SPEC.md` (the card contract) or to `query.py`/`console.py` behavior.
- Authoring/ingestion redesign: `init/build/check/normalize/ingest` are only REGISTERED and delegated, not reworked; they are not part of the consumption spec.
- New KB content, new frameworks, or corpus changes.
- MCP transport changes (stays stdlib stdio JSON-RPC) and any networked/remote server mode.
- Retrieval/performance optimization (BM25 tuning, caching) — behavior-preserving only.
- Turning `diagnose` into semantic classification — it stays curated symptom→dimension routing, described honestly.
- Multi-KB write/authoring fan-out — authoring ops remain single-KB.
