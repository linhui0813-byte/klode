# TDD Plan: Multi-format source ingestion (PDF, EPUB, DOCX, HTML/XHTML, TXT)

Scope: turn `lode ingest` from PDF-only into a content-sniffing, multi-format extractor front-end that rejoins the existing normalize → build → check path. Core stays stdlib-only (Python 3.11+); optional backends stay lazy and skippable. Every WI below is independently verifiable with `python3 -m unittest discover -s tests` and **zero optional backends installed**.

Proposed layout (mirrors the `opspec.py` declarative-registry precedent): a new `lode/lib/formats/` package — `__init__.py` (the `Extraction` dataclass, `FormatHandler` protocol, the `HANDLERS` registry tuple, and `route()`), plus `txt.py`, `html.py`, `epub.py`, `docx.py`, `pdf.py`. `lode/lib/ingest.py` becomes the orchestrator (route → extract → quality → `normalize.process` → guard → write → provenance). Existing PDF tier logic (`_pdftotext`/`_xberg`/`_docling`, `choose_and_extract`) moves behind the PDF handler unchanged.

Assertion levels below cite `policy-core` (Level 1 = return-value output; Level 2 = side-effect, i.e. read the written `.txt`/`PROVENANCE.jsonl` back; Level 3 = real end-to-end through `ingest()`/CLI `main()`; Level 5 = mock only the lazy-import boundary, then assert observable output). No stdlib is mocked; EPUB/DOCX/HTML fixtures are built in-memory with real `zipfile`/`html`.

### WI-4: EPUB handler (zipfile + OPF spine order + zip-bomb/traversal guards)
**Status:** DONE — 2026-07-30
**Changed:** lode/lib/formats/epub.py, lode/lib/formats/_base.py (SafeZip), tests/test_formats.py
**Verified:** python3 -m unittest discover -s tests (378 passed, 1 skipped)
- **Description**: Stdlib EPUB extraction: open with `zipfile`, read `META-INF/container.xml` → OPF path → parse the `<manifest>`/`<spine>` with `xml.etree`, resolve spine `itemref idref` → manifest `href` **in spine reading order**, read each XHTML entry in memory, and reuse WI-3's HTML text extraction. `sniff`: `PK\x03\x04` head AND `mimetype` entry equals `application/epub+zip`.
- **Acceptance criteria**:
  - [ ] Text is concatenated in **OPF spine order**, not zip/alphabetical order (fixture proves order differs from both).
  - [ ] Reads entries in memory via `ZipFile.open`/`read`; never calls `extractall`; never writes to disk during extraction.
  - [ ] **Zip-bomb guard**: refuses (raises a typed error) when any entry's `ZipInfo.file_size` (or cumulative uncompressed size) exceeds a configured cap, before decompressing that entry.
  - [ ] **Path-traversal guard**: an entry name containing `..` or an absolute/rooted path is refused, never used to open/write outside the archive.
  - [ ] A `.epub` that is actually a bare zip with no `mimetype` fails `sniff` (falls through to other handlers), and a truly malformed EPUB raises a clear error rather than writing a partial `.txt`.
  - [ ] `format == "epub"`, `handler == "epub"`.
- **Required tests**:
  - in-memory EPUB whose spine orders chapters c3→c1→c2 while the zip stores them c1,c2,c3 → extracted text has the three chapter markers in spine order — assertion level: Level 1
  - manifest item absent from the spine (e.g. `nav.xhtml`) is excluded from output — assertion level: Level 1
  - entry declaring `file_size` beyond the cap → extraction raises the zip-bomb error and produces no text — assertion level: Level 1
  - entry named `../evil.xhtml` → refused with a traversal error; nothing written outside a tmpdir (assert tmpdir unchanged) — assertion level: Level 2
  - bare zip missing the `application/epub+zip` mimetype → `sniff` returns `False` — assertion level: Level 1
  - entities/markup inside chapters are decoded via the shared HTML path (`&amp;` → `&`) — assertion level: Level 1

## Risks & Assumptions
- **Assumption (verified)**: no code reads `PROVENANCE.jsonl` fields — grep of `lode/` and `tests/` shows provenance is write-only from `ingest.py`, so generalizing `source_pdf`→`source` is safe. If a downstream tool outside this repo parses `source_pdf`, WI-10 breaks it; mitigate by keeping `source_pdf` as a duplicate alias if needed.
- **Zip-bomb cap is a policy choice**: the uncompressed-size cap must be generous enough for real books yet block bombs. Risk of false-refusal on large legitimate EPUBs; make the cap a named constant and document it. Trusting `ZipInfo.file_size` alone is insufficient against a lying header — enforce a *cumulative decompressed* cap while streaming, not just the declared size.
- **`normalize.process` needs a word list** (`cfg.dict_path`, default `/usr/share/dict/words`); on a machine without it, ctrl/ascii repair degrades (as `normalize` already documents). Ingest must not hard-fail when the dict is absent — it should degrade like `normalize`'s dry-run path. Test both presence and absence.
- **HTML block-vs-inline break heuristic** can mangle whitespace (mid-word breaks, lost spaces). This is a quality risk, not a correctness one; anchor it with explicit inline-vs-block fixtures (WI-3).
- **DOCX/EPUB namespace handling**: real-world files vary (namespace prefixes, `xml:space="preserve"`). Fixtures must include a namespaced document; naive string tag matching will silently drop content.
- **`corruption`/`control_char_ratio` thresholds are empirical**; a wrong garbage-guard threshold could refuse a legitimately short/odd source or admit garbage. Keep thresholds as named constants with the existing `CLEAN_THRESHOLD`/`MIN_WORDS` and cover boundary cases. Note: PDF's `MIN_WORDS=200` clean-layer heuristic must stay **PDF-only** — a legitimately short TXT/HTML must not be rejected by it.
- **Sniff head size**: too small a head window can misclassify (e.g. leading whitespace/comments before `<html>`); choose a head large enough to survive leading BOM/whitespace and test the wrong-extension cases explicitly.
- **`test_parity.py`/`test_opspec.py` coupling**: `ingest` stays a single op in `opspec.OPS`; multi-format is an internal expansion, so parity tests should be unaffected — but WI-11 must run them to confirm no drift.

## Deferred / Out of Scope
- No change to the storage model, card format, `build`/`check`/`verify`, or the normalize algorithm itself — handlers only produce raw text that rejoins the existing pipeline.
- No new MCP tool or op-id for ingest; ingest remains CLI-only per `opspec.OPS`.
- No streaming/very-large-file handling beyond the zip-bomb cap; no encrypted/DRM EPUB support.
- No RTF, ODT, MOBI, AZW, or image-only formats in this pass.
- No auto-installation of optional backends; `pipx inject lode <pkg>` stays the manual, documented path.
- No mandatory runtime dependency added to the core, per the hard invariant.
