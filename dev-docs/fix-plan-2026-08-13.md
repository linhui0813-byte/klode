every objection below is backed by a check that was actually run; where a check contradicted the
first draft of this plan, the draft lost and the change is different now.

## N-B — the plaintext transport guard is bypassable with no opt-in (High)

**Mechanism.** `settings._is_private_host` short-circuits on `if "." not in h: return True`, so any
single-label host is classified private — the rule exists to allow `http://docling` in Docker/k8s.
A decimal-integer IPv4 has no dot, so it takes that branch before `ipaddress` is ever consulted.

```
8.8.8.8                resolves->8.8.8.8      guard: rejected
134744072              resolves->8.8.8.8      guard: ACCEPTED
0x08080808             resolves->8.8.8.8      guard: ACCEPTED
0300.0250.0010.0010    resolves->192.168.8.8  guard: rejected
```

`klode ingest` uploads whole documents to this endpoint. `KLODE_ALLOW_INSECURE_HTTP` is not needed;
the guard simply does not fire. Note the inconsistency in the last row: a *dotted* octal form is
rejected (it has dots, `ip_address()` refuses leading zeros, so it falls through to "public DNS
name"), while the bare decimal form sails through. The guard is stricter on the obscure spelling
than on the reachable one.

**Change.** In `_is_private_host`, normalise before classifying: if the host is entirely digits, or
`0x`/`0o`-prefixed, parse it as a 32-bit integer and classify the resulting `IPv4Address`. Anything
that parses as *any* IP spelling is classified as an IP, never as a container name. The single-label
allowance then applies only to hosts that cannot be an address.

**Test.** Parameterised over `8.8.8.8`, `134744072`, `0x08080808`, `010.010.010.010`,
`::ffff:8.8.8.8`, and the legitimate `docling` / `docling-serve` — public spellings rejected,
container names still allowed. That last half matters: over-tightening breaks the documented
deployment, which is why the loose rule was written.

**Assertion left behind.** A property test asserting `_is_private_host(h)` agrees with
`ipaddress.ip_address` for every host that parses as an address in any spelling.

## F1 — a glob metacharacter in the library path defeats the fail-closed linter (High)

**Mechanism.** `glob.glob(os.path.join(cfg.cards, "*.md"))` hands the *whole* joined string to
`glob`, which interprets `[ ] * ?` anywhere in it, including the directory prefix. A library under
`.../kb[1]/` matches nothing. `check.py:161` records `unmeasured` only `if cards:` — and the bug's
effect is to make `cards` empty, so the abstention guard cannot fire. Proven: `check` exits **0**
with `OK: 0 errors` over a citation that resolves nowhere, and `build` rewrites `INDEX.md` to empty
and exits 0. `query._md_files` uses `Path.glob` and is immune, so the lens layer stays visible while
the grounding layer empties — the KB half-works.

**Change — corrected from the draft.** The draft proposed swapping to `Path.glob`. That is wrong;
three checks killed it:

| check | result |
|---|---|
| dotfile membership | `glob.glob("*.md")` excludes `.hidden.md`; `Path.glob` includes it. Changes 9 of 10 sites. An Emacs lock file `.#card.md` is a symlink to `user@host.pid` — it would become a card and crash `read()`. |
| `**` semantics | `normalize.py:341` takes a **user** `--pattern`. `glob.glob` without `recursive=True` treats `**` as one level (16 hits on a sample tree); `Path.glob` recurses (61) and refuses to follow directory symlinks (38 → 0 on another). |
| absolute patterns | `Path.glob("/abs/*.txt")` raises `NotImplementedError`; today `os.path.join` discards the base and the realpath filter contains it safely. |

The correct fix is `glob.escape()` on the **directory segments only**, leaving the trailing pattern
live. This preserves dotfile exclusion, `**` semantics, symlink traversal and sort order exactly.

Escape each segment, not just the base — config validation rejects only `/`, `""`, `.` and `..`, so
`shelves = ["books[1]"]` is accepted (verified) and is a second live injection point:

```python
os.path.join(glob.escape(str(cfg.lib)), glob.escape(shelf), "*.txt")
```

Ten sites (the draft said eleven; recount): `common.py:277,283`, `build.py:47,95,116`,
`check.py:235,271,275,395`, `normalize.py:341`. At `normalize.py:341` escape only `cfg.lib` — the
pattern is the user's and must stay live. Convert to `str` **before** sorting where results are
sorted: `sorted(map(str, …))` and `sorted(map(Path, …))` disagree across directories
(`['/x/a-/z.txt', '/x/a/z.txt']` vs `['/x/a/z.txt', '/x/a-/z.txt']`).

**Test.** Copy the fixture KB into a tmpdir whose name contains `[`, plus a shelf named `books[1]`;
assert the real card and source counts, and that a citation broken in that copy is caught.

**Assertion left behind — corrected.** The draft's tripwire ("cards dir has `*.md` but
`card_files()` returned none") false-fires on a dir holding only the excluded `INDEX.md`/`README.md`
and crashes on an unreadable dir. Compare against the *same* exclusion set and treat an `OSError`
from `scandir` as its own reported error, not a crash.

## F2 — an ordinary rubric edit permanently bricks the rubric (High)

**Mechanism.** `cmd_approve` (`gate/__main__.py:167`) calls `_load_doc`, which runs `_spec.parse`
on the *unmodified* doc — still `human_approved` with a stale `approved_digest`. `parse` raises
"the rubric has been EDITED since it was approved"; `_load_doc` turns it into `SystemExit`. The
demotion to `candidate` and the digest pop that would clear the guard are at lines 168–169, two
lines too late. `repin` shares the loader and is blocked identically. Verified from a pristine
fixture by editing one level descriptor: `check`, `approve` and `repin` all exit 1, and the only
escape is hand-deleting `approved_digest`, which no message mentions.

**Change.** `_load_doc(path, *, allow_stale_approval=False)`; when True, reset
`admission`/`approved_digest` to candidate *before* `parse`. Both `cmd_approve` and `cmd_repin`
pass True.

**Why that is not a security regression** (the refute pass's main challenge, and it survives):
`approve` has no prompt — "human approved" already means "a human ran this command". The digest's
job is to make approve-then-edit *detectable*, not unrecoverable, and re-running `approve` is the
human re-approving. `repin` revokes approval unconditionally, so it needs the same door.

**Also fold in.** `_load_doc` lacks the hostile-JSON boundary `spec.load` has: an oversized JSON
integer leaks a raw `ValueError` and a deeply nested fingerprint leaks `RecursionError`. Same file,
two readers, one hardened. Give `_load_doc` the same size cap and exception boundary.

**Change (message).** `spec.py:469` must name a recovery that works.

**Test.** Pristine fixture → edit a descriptor → `approve` exits 0 → `check` exits 0. Plus the
hostile-JSON cases against `_load_doc`.

**Assertion left behind.** Any state from which `check` fails with a message naming `approve` must
be a state from which `approve` exits 0.

## F3 — the Go/Recycle threshold is applied to a rounded score (High)

**Mechanism.** `review.py:201` rounds before comparing, so any exact mean in `[hurdle−0.5, hurdle)`
is promoted. Verified end to end: a 0..3 / 0..7 rubric scored 1 and 6 is exactly 59.5238% and
returns **Go** at hurdle 60. The bias is one-directional — 12 false-Go configurations across
two-criterion rubrics with maxima 2..10, and zero false-Recycle (arithmetically impossible).
`Verdict.defects` already compares exactly, with a comment warning against precisely this.

**Change.** Compare the exact `Fraction`; display the floor.

The draft left display as an open question. It is not a judgement call — for an **integer** hurdle,
`floor(x) ≥ h ⟺ x ≥ h`, so flooring can never contradict the decision. Exhaustively, over every
two-criterion rubric with maxima 2..10 and every hurdle 0..100:

```
display=round : 1338 cases where the shown score contradicts the correct decision
display=floor :    0
```

The theorem needs its precondition, which does not hold today: `review_draft` validates
`0 <= hurdle <= 100` but not integer-ness, so `hurdle=59.6` is accepted. Add the type guard as part
of this change — otherwise the invariant is asserted rather than true.

Safe to change: `Verdict.score` is only rendered (`cli.py:803`, `services.py:412`); nothing derives
a decision from it.

**Test.** A mixed-scale fixture rubric (0..3 and 0..7) asserting `Recycle` at 59.5238%, plus a
property test over maxima 2..10 asserting `decision == ("Go" if exact >= hurdle else "Recycle")`
and `floor(score) >= hurdle iff Go`.

**Assertion left behind.** The mixed-scale fixture itself. Both existing rubrics use uniform scales
whose means land on integers — that is *why* 874 tests miss this. Add it to the `corpus` CI job
alongside `pacing` and `cadence`.

## N-C — calibration pins the rubric but not the judge (High)

**Mechanism.** `Calibration.covers()` compares `rubric_digest` only. The class docstring is careful
that rewording a descriptor produces a different instrument — but the *other* half of the
instrument, the judge, is unpinned:

```
model=measured-model                  permutations=2  calibrated_for(rubric)=True
model=a-COMPLETELY-different-model    permutations=1  calibrated_for(rubric)=True
```

An agreement number measured with one model at `permutations=2` transfers intact to a different
model running undebiased. `calibrated` is the flag the review service uses to drop
`non_production` — the single bit that says a verdict is authoritative.

**Change.** Extend `Calibration` with the instrument identity it was measured against — at minimum
`model` and `permutations`, plus a prompt/scorer version constant bumped when `STEPS_PROMPT` or
`FORM_PROMPT` changes. `covers()` requires all of them to match. Keep the field optional-with-None
for one release so existing records fail closed rather than crash.

**Test.** Same rubric, different model → `calibrated_for` False. Same rubric, `permutations` 2→1 →
False. Exact match → True.

**Assertion left behind.** A test that hashes `STEPS_PROMPT`/`FORM_PROMPT` and fails when either
changes without the version constant moving — otherwise the prompt drifts and the calibration
silently outlives the instrument it measured.

## N-A — `git ls-files` option injection blanks the copyright-leak guard (Medium)

**Mechanism.** `check.py:388` interpolates `cfg.guard_relpaths` into `git ls-files -z <paths>` with
no `--` separator. Shelf validation rejects only `/`, `""`, `.`, `..`, so `shelves = ["--others"]`
is accepted; with `[library].dir = ""` the relpath *is* `--others` and git consumes it as an option:

```
git -C <root> ls-files -z --others
rc: 0 | stdout records: ['library.toml']      # the tracked leak.txt is NOT listed
```

A genuinely git-tracked copyrighted source goes unreported and `check` stays green. Precondition:
`dir` must be empty, since otherwise the relpath is prefixed (`library/--others`) and cannot look
like an option — narrower than a bare read of the code suggests, but real, and the guard is exactly
the one that must not fail open.

**Change.** `git ls-files -z --literal-pathspecs -- <paths>`. Both tokens: `--` fixes option
injection, `--literal-pathspecs` fixes the separate problem that git pathspecs glob by default
(a shelf named `books[1]` is a wildcard there too — the same class as F1).

**Assertion left behind.** Extend shelf validation to reject a leading `-`, so the defect is closed
at the boundary as well as at the call site. Belt and braces is correct here: this guard's failure
mode is publishing copyrighted text.

## F5 — releases to PyPI run no tests (Medium)

**Mechanism.** `workflow.yml` fires `publish` on `push: tags: ["v*"]` with `needs: build` only.
`tests.yml` fires on `push: branches: ["**"]`, which does not match tag refs. No tag push runs the
suite, the fixture lint, or the zero-dependency probe.

**Change.** Add `on: workflow_call:` to `tests.yml`; `workflow.yml` calls it and `publish` gains
`needs: [build, test]`.

**Assertion left behind.** Extend `tests/test_repo_hygiene.py` to assert the publish job
transitively depends on the test job. **Constraint:** CI deliberately installs nothing
(`python -m unittest`, no pip), so this test must parse the workflow YAML with stdlib only. A test
importing `yaml` passes locally and fails in the one place it needs to run.

## F6 — odd `permutations` unbalances the debiasing, and the constructor validates almost nothing (Medium)

**Mechanism.** `llm_judge.py:225` uses `reverse=bool(i % 2)`, so 3 gives 2 forward / 1 reversed —
position bias retained at 1.5× the cost, while the module claims first-order cancellation. Worse,
the constructor's only guard is `permutations < 1`:

```
permutations=True   ACCEPTED -> stored True     # True == 1, slips the guard; one forward run
permutations=2.0    ACCEPTED -> stored 2.0      # TypeError later, inside range()
permutations=3      ACCEPTED -> stored 3
permutations=17     ACCEPTED -> stored 17       # above the settings cap of 16
```

**Change.** One domain, enforced in both places. `SPEC` gets `choices=(1,2,4,6,8,10,12,14,16)`;
`LLMJudge.__init__` rejects non-`int`, `bool`, and anything not in `{1} ∪ evens ≤ 16`. `1` stays
legal — it is the cheap explicitly-undebiased mode and `tests/test_llm_judge.py:125` depends on it
— but the class docstring must say the guarantee is conditional on an even count, not
unconditional.

Existing tests survive: `test_settings.py:197–198` only assert `ValueError` (0 and 99 still
rejected, message differs); `test_llm_judge.py` uses 1, 2 and 4; `test_settings.py:492` asserts
`"5 per criterion"` from `permutations=4`.

**Test.** `permutations=3` refused with a message naming why; `True` and `2.0` refused at the
constructor, not at `range()`.

## F4 — the settings error prescribes a key that breaks the settings file (Medium)

**Mechanism.** `settings.py:297` says to set `[ingest].allow_insecure_http = true`. That key is not
in `SPEC`; `load()` rejects unknown keys, so following the instruction makes every
settings-resolving command fail. The working hatch, `KLODE_ALLOW_INSECURE_HTTP`, is named only in
the CHANGELOG and the function body.

**Change — reversed from the draft.** The draft proposed adding the key to `SPEC` to make the
message true. Two independent checks say fix the message instead:

1. Scope. A persisted `true` blankets `ingest.docling_url`, `ingest.marker_url`, and any URL setting
   added in a later release, with no re-consent. The env var must be re-supplied per invocation.
   The ephemerality is the control, not an accident.
2. It would not even work. `_validate_url` reads the environment directly (`settings.py:291`), so
   adding the key resolves it (`key resolves: True file`) while transport validation still refuses
   (`key affects transport: NO`). The draft's "assert the file loads" test would pass while the
   remedy stayed broken — a green test over a defect, which is the failure this repo is built
   against.

So: change the message (and the stale `[ingest].allow_insecure_http` reference in the docstring at
line 319) to name `KLODE_ALLOW_INSECURE_HTTP`, and list that variable in `klode settings` output.

**Assertion left behind.** A generic test: every `[section].key` token appearing in any `SPEC` help
text or raised settings message must exist in `SPEC`. This is what would have caught the original.

## F7 — the CLI prints a command that resolves on one machine (Low)

Four sites, not three: `cli.py:409` (`lib consult`), `410` (`lib diagnose`), **`476`** (`lib zoom`
— missed in the first pass), `557` (`lib consult`). `lib` is the pre-rename tool and exists at
`~/.local/bin/lib` here, so the hints run locally and are `command not found` everywhere else.

**Change.** Emit `klode`, derived from `parser.prog` rather than hardcoded.

**Assertion left behind — corrected.** The draft's "no user-facing string *begins with* a non-klode
command" catches **none** of the four, since all are mid-string. Walk the AST for string constants
and match a command token anywhere in the literal.

## F8 — `Config` path parameters raise `AttributeError` on a `str` (Low)

Three entry points, not one: `Config.load(config_path=str)`, `Config.load(start=str)`, and
`Config.find(str)` all raise `AttributeError: 'str' object has no attribute 'resolve'`. The module
promises `ConfigError`, never a confusing error three modules deep.

**Change.** Coerce with `Path(...)` at all three, and wrap resolution failures in `ConfigError` —
`Path("bad\0path").resolve()` raises a bare `ValueError` that would otherwise escape the documented
contract.

## Sequencing

Eleven commits, one per defect, suite green after each. Order: **N-B, F1** (the two that make wrong
look right), then **F2, F3, N-C** (gate correctness), then **N-A, F5, F6, F4**, then **F7, F8**.

F1 lands early because a KB at a metacharacter path makes every other check unmeasurable — no
finding downstream of it can be trusted until it is fixed.

Two changes are user-visible and belong in the CHANGELOG under a behaviour heading: F3 (a draft
that previously scored Go at the boundary now scores Recycle — verdicts move) and F6 (odd
`permutations` values are now refused). N-C changes the `Calibration` constructor signature; the
new fields default to None and fail closed, so existing records stop claiming calibration rather
than crashing — that is the intended migration and should be said out loud.
